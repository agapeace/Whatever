# Whatever - мобильное iOS приложение для просмотра футбольных ивентов.

## Главный экран (MainScreen):

Главный экран содержит в себе поисковую строку и блок информации прямых трансляций.

### Визуальная составляющая:
1. Поисковая строка
2. Блок прямых транслируемых матчей имеет следующие поля:
   * Время начало игры
   * Текущее игровое время
   * Картинки команд
   * Названия команд
   * Счет команд
3. Транслируемые матчи группированы по одинаковым турнаментам в различные секции

![Снимок экрана 2025-07-03 в 12 55 30](https://github.com/user-attachments/assets/cfe4aab7-3065-4821-a18e-b4be1395a0c0)


### Логика Экрана (MainScreen):
1. Используются два UI-элемента: UISearchTextField и UICollectionView.
2. При нажатии на UISearchTextField осуществляется переход на экран SecondScreen с использованием UIView.animate.
3. При выполнении метода viewDidLoad() отправляется запрос на RapidAPI для получения JSON с футбольными играми, которые проходят в данный момент.
4. Запрос на RapidAPI и остальная бизнес-логика выполняются через ViewModel текущего экрана, через который обрабатываются действия пользователя.
5. При успешном получении данных из API происходит обновление UICollectionView и заполнение ячеек и секций соответствующей информацией.

## Экран поиска Информации (SecondScreen)

Данный экран содержит поисковую строку, кнопку отмены и блок информации о футболистах

### Визуальная составляющая:
1. Поисковая строка, которая находит подробную информацию о футболистах
2. Блок информации о футболистах имеет следующие поля:
   * Картинка Игрока
   * Фамилия и Имя Игрока
   * Картинка Клуба
   * Название Клуба Игрока

![Снимок экрана 2025-07-03 в 11 32 16](https://github.com/user-attachments/assets/2dfb43df-c967-478b-8c82-956ee565eb0d)

### Логика Экрана (SecondScreen):
1. После добавления имени игрока или футбольной команды в поиск необходимо нажать на кнопку Enter, чтобы отправить запрос.
2. Во время выполнения запроса на экране используется UIActivityIndicatorView для отображения загрузки.
3. После успешной обработки данных обновляется UICollectionView и заполняются ячейки с информацией.
4. Каждое изображение загружается отдельно с помощью Kingfisher.
5. При нажатии на кнопку "Cancel", приложение возвращает пользователя на главный экран
6. В связи с особенностями API не вся информация о футболисте доступна в одном запросе. По этой причине используется prefetch collectionViewCell.
7. В методе prefetch отправляются запросы к двум дополнительным API для получения информации, которая отображается при нажатии на ячейку.
8. Для предотвращения параллельных запросов по одному и тому же id используется коллекция Set для отслеживания id, по которому в данный момент производится запрос.
9. При нажатии на ячейку срабатывает механизм переноса не след. экран с помощью метода pushViewController.
10. При переходе на след. экран передается вся детальная информация о футболисте.

##  Экран Детальной Информации (PlayerInfoViewController)

Данный экран содержит в себе 3 основных блока информации

### Визуальная составляющая:
1. Первый блок
   * Картинка Игрока
   * Фамилия и Имя Игрока
   * Градиентный задний фон
2. Второй блок
   * Картинка Клуба
   * Название Клуба
   * Дата истечения контракта игрока с клубом
   * Национальность: Флаг + Код Страны
   * Возраст
   * Рост
   * Сильная нога
   * Игровая позиция
   * Игровой номер
   * Рыночная цена
3. Изоброжение позиций игрока на футбольном поле

   ![detail](https://github.com/user-attachments/assets/25e56ef5-f3d7-4d26-9c07-40ef1aa01ed8)

### Логика экрана (PlayerInfoViewController)

1. Первый блок:
   * Как ранее упоминалось, на экране SecondScreen в методе prefetch выполняются запросы к двум дополнительным API, информация из которых в дальнейшем используется для отображения.
   * В JSON-ответе содержится атрибут с цветами, принадлежащими клубу игрока. Эти цвета используются для создания градиентного заднего фона.
   * Также выполняется запрос через Kingfisher для получения фотографии игрока.
2. Второй блок:
   * В JSON есть различные поля типа Int, представляющие собой timestamp. Одно из таких полей — дата истечения контракта. В классе ViewModel экрана используется форматирование этого значения из timestamp в текстовый формат.
   * В JSON содержится код страны, который передаётся в метод для получения флага страны в текстовом виде (например, 🇺🇾).
   * В JSON также есть дата рождения игрока, которая форматируется в методе ViewModel для отображения возраста или полного формата даты.
3. Третий блок
   * В JSON передается массив позиций в формате String. Для каждого элемента этого массива вызывается метод, который добавляет на изображение поля соответствующую маркировку позиции.
   * Таким образом, если у игрока несколько позиций, в изображение поля добавляются все соответствующие маркировки этих позиций.
